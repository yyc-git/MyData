## 最佳起步路径

**Step 1：先跑通 Demo（1 天）**

用 Three.js + WebSocket，做一个最简单的 Demo——两个方块在同一个场景里移动。不用 monorepo、不用 TSRPC、不用任何工程化。30 行服务端代码 + 50 行前端代码。

目标是：看到"网络能通"。

**Step 2：状态同步（3 天）**

不要帧同步。直接上状态同步——服务端权威，全量状态下发。你会踩浮点数、踩竞态、踩断连——每个坑都是值的学习机会。

**Step 3：工程化（1 周）**

当代码超过 1000 行时，进入 monorepo 阶段。分 packages、统一构建、共享类型。同步引入 TSRPC 或其他 RPC 框架。

**Step 4：部署上线（3 天）**

WebSocket 游戏的服务端部署和普通 Web 应用不一样。需要：
- 支持长连接的平台（SCF/AWS Lambda + WebSocket Gateway）
- 心跳保活
- 冷启动优化
- 日志监控

**Step 5：自动化（持续）**

引入 AI 工具（OpenCode/OpenClaw）做编码和调度。写 Skill 固化流程，从手动到半自动到全自动。

## 技术栈推荐

| 模块 | 推荐 | 理由 |
|------|------|------|
| 渲染 | Three.js | WebGPU 就绪，生态成熟 |
| 通信 | WebSocket | 实时性足够，浏览器原生支持 |
| RPC 框架 | TSRPC 或 ws | 全链路类型安全 |
| 状态管理 | SoA TypedArray | 性能好、WebGPU 就绪 |
| 部署 | SCF / AWS Lambda | Serverless，按量付费 |
| AI 调度 | OpenClaw | Skill 系统，流程可执行 |
| AI 编码 | OpenCode | 终端 AI Agent，上下文窗口大 |

## 从 Builder 到 Conductor

整个 Vibe Coding 多人游戏系列想传达的核心观点是：

> **你不需要成为编码专家才能做多人游戏。但你需要成为"指挥者"——知道做什么、怎么分步、怎么验收。**

传统多人游戏开发需要懂网络编程、帧同步、回滚、防作弊。Vibe Coding 环境下，你可以用更简单的方式做到同样的事情——状态同步、纯函数共享层、开闭原则、隔离部署。

AI 负责"怎么做"，你负责"做什么"。
