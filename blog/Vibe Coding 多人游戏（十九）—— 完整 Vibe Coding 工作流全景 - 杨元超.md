## 完整工作流

```
你（一句话需求）
    │
    ▼
┌──────────────────────────────────────┐
│          OpenClaw 调度层              │
│                                      │
│  1. 读取 Skill（可执行 SOP）          │
│  2. 读取项目上下文（agent-context.md）│
│  3. 生成 Brief（需求 + 红线 + 测试）  │
│  4. 调度 OpenCode                     │
│                                      │
└──────────┬───────────────────────────┘
           │ Brief
           ▼
┌──────────────────────────────────────┐
│          OpenCode 编码层              │
│                                      │
│  1. 读文件 → 理解代码                 │
│  2. 改代码                            │
│  3. tsc / rescript build             │
│  4. 发现错误 → 自修                    │
│  5. 跑测试 → 失败 → 继续修            │
│  6. 全部通过 → 输出报告               │
│                                      │
└──────────┬───────────────────────────┘
           │ 代码 + 测试通过
           ▼
┌──────────────────────────────────────┐
│          验收 + 部署                  │
│                                      │
│  1. BDD 测试（7 场景覆盖）            │
│  2. E2E 双窗口验证（需要时）          │
│  3. deploy-scf.js 上线               │
│  4. 部署后自动 log 检查              │
│  5. 通知完成                          │
│                                      │
└──────────────────────────────────────┘
```

## 一个完整迭代的例子

**需求**："修复退房后 isEnterGame 标志位未重置的 bug"

**Step 1：你说话**
> 兄弟，修复退房后 isEnterGame 标志位未重置。

**Step 2：OpenClaw 调度**
1. 匹配 `gts-dev-fix` Skill
2. 读取 `agent-context.md`（项目结构、编码红线、测试命令）
3. 生成 Brief：

```
## 目标
修复退房后 isEnterGame 标志位未重置

## 文件范围
- packages/room-service/src/models/Game.ts (dispose)
- packages/room-service/src/state/State.ts (flag)

## 红线
- 改 .ts 再 tsc
- 不改 .js
- 不引入新依赖

## 测试
- 新增集成测试验证退房后 flag=false
```

4. 调度 OpenCode 执行

**Step 3：OpenCode 编码**
```
→ 读取 Game.ts dispose 逻辑
→ 发现 dispose 未重置 isEnterGame
→ 修改：dispose 时重置 flag
→ tsc → 编译通过
→ 跑 BDD → 测试通过
→ 新增集成测试 → 红 → 修复 → 绿
→ 输出修改总结
```

**Step 4：验收 + 部署**
```
→ BDD 测试全部通过（335 个）
→ deploy-scf.js
→ 部署到腾讯云 SCF
→ 双环境验证
→ 通知"部署完成"
```

全程耗时：~10 分钟。AI 写代码 8 分钟，你说话 2 分钟。

## 治理制度

流程跑起来后，需要一些制度让它不掉链子：

**入口检查**：每次收到新消息先检查后台任务是否完成，完成先汇报再接新活。

**先汇报再继续**：OpenCode 出结果后，必须出声总结再下一步。不能默默处理完等兄弟发现。

**等确认发通知**：需要兄弟决策时，发桌面通知，不能假设对方在聊天工具前。

**双通道通知**：重要事件走两个通道（桌面弹窗 + 聊天工具），确保不漏。

## 工作流的关键参数

| 阶段 | 典型耗时 | 谁来监督 |
|------|---------|---------|
| 需求描述 | 1-2 分钟 | 你 |
| Brief 生成 | 5 秒 | OpenClaw |
| OpenCode 编码 | 3-15 分钟 | OpenClaw（连续 poll） |
| 编译测试 | 自动 | OpenCode |
| 验收 | 1-2 分钟 | 自动化 |
| 部署 | 30 秒 | deploy-scf.js |

从需求到上线，最慢 20 分钟，最快 5 分钟。

## 为什么不是全自动化

你可能想问：为什么不把"你"也去掉？让 AI 自己提需求、自己开发、自己上线？

答案：**因为"做什么"比"怎么做"难一万倍。**

AI 目前能做的很好的是"怎么做"——写代码、跑测试、部署。但"做什么"需要深刻理解用户需求、权衡取舍、判断边界——这些仍然是人类的领域。

> **Vibe Coding 不是"不用人编程"，而是"人做决策，AI 做执行"。**
